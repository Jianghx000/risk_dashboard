# 行内 AI 智能工场契约规格（本地模拟基准）

本文件是《AI智能工厂业务编排节点文档（全）》（57 页，用户提供 PDF）的文字化契约提炼，作为本目录对齐行内平台的规格来源与迁移校验清单。原文档为图片型 PDF，不便引用与 diff；本文件只记契约，不复述操作截图。两者冲突时以行内平台实际行为为准，并回改本文件。

文中"本地"指本目录（01-ai-workflow-service，快照自本地基础设施 AI-workflow-service）；"扩展"指行内文档中没有、为本地调试与过程可见性而增设的约定，迁移时必须显式处理（见第 12 节）。

## 1. 节点类型总表

业务编排由节点组成，节点是组成业务编排的基本单元。行内平台支持 14 类能力（函数表达式是变量取值方式，不是节点）：

| 节点 | 职责 | 本地对齐状态 |
| --- | --- | --- |
| 开始 | 编排起点；入参即对外 API 入参（JSON 或 FormData），可声明类型 | `INPUT_PARAMS` 声明 + `aiworkflow.params` 校验 + `workflow_check` 装配期检查 |
| Prompt | 配置 Prompt 与模型，生成内容作为数据的一部分 | `graph_kit.make_prompt_node`（输出格式三选/输出参数声明/异常忽略/`LLMParams` 高级参数） |
| 条件选择器 | 依据条件走不同分支（IF/ELSEIF/ELSE，AND/OR） | `aiworkflow.conditions`（操作符集 + AND/OR + 路由） |
| RAG | 从预配置知识库按关键词检索文档片段 | `aiworkflow.rag`（词法模拟检索：keyword/semantic/hybrid + 阈值 + top_k + 来源） |
| API | 与外部系统或服务交互（从注册列表选择） | `nodes.make_api_node`（ApiSpec 注册声明 + 异常忽略） |
| AI 能力 | 使用企业级/领域级公共 AI 能力（插件形态同 API） | 形态同 API 节点（`make_api_node` 可承载） |
| MCP | 调用 MCP Server 内的工具 | `nodes.make_mcp_node`（server/tool 声明；协议对接留行内接入时替换 invoke） |
| 脚本 | 编写代码处理输入变量生成返回值（python/Node.js 沙箱） | `nodes.make_script_node`（params 入参/必须返回 dict/3s 超时/异常忽略） |
| 业务编排 | 引用已有业务编排作为子流程（嵌套 ≤2 层，禁自引用） | `nodes.make_subflow_node`（装配期深度校验；自引用/环由 `workflow_check` 检查） |
| Agent | 模型自主规划工具调用（Function call / ReAct） | `aiworkflow.agent.make_agent_node`（Function call 循环/工具失败重试一次/hidden_args/输出 steps+output） |
| 循环组件 | 遍历数组执行子流程（严格串行，不支持嵌套） | `nodes.make_loop_node`（串行轮次/中间变量跨轮/装配期禁嵌套/输出数组） |
| 中间信息输出 | 执行过程中向用户输出消息（String/Object，可流式） | `nodes.make_message_node`（String 走 `data.output`，Object 即 data） |
| 结束 | 汇合参数组成 JSON 作为最终结果输出（可视化/自定义） | DONE 帧 + `nodes.make_end_output`（`${state 键}` 模板声明） |
| 函数表达式 | 变量值经内置函数计算（见第 10 节） | `aiworkflow.expressions`（第 10 节函数族全量 + `${}` 引用与运算符的安全求值） |

工作流级约束（第 11 节）由 `aiworkflow.workflow_check` 在图装配期检查（回边声明、循环嵌套、子编排深度、入参声明、死路、入口唯一）；limit 工作流已在 `build_graph` 接入，未声明的回边装配即失败。

## 2. 变量与引用模型

- 每个节点入参两类来源：引用（前置节点输出或环境变量）与输入（静态自定义值，带类型）。
- 只有连线可达的上游节点可引用；并行分支之间不可互引。
- 节点运行结果存储在"输出变量名"下的 key 内；输出类型为 Object 时可声明输出参数（属性名 + 类型），后置节点按属性引用。
- 开始节点有平台内置变量 `systemInput`，引用开始节点入参须经它（如 `systemInput.name`）。
- Prompt 与表达式中以 `${变量}` 形式引用，如 `${question}`、`SUM(${开始/numbers/number1}, ${开始/numbers/number2})`。
- 本地对应：langgraph state 键即"输出变量名"；节点产出 state 键的命名应与行内输出变量声明一一对应，迁移时逐键映射。

## 3. 流式输出契约（SSE 帧）

行内流式输出为纯 `data:` 帧（无 `event:` 行），每帧类型由 JSON 内 `type` 字段区分。帧外壳固定：

```
data:{"returnCode":"SUC0000","errorMsg":null,"data":{...},"sessionId":null,"type":"DATA"}
data:{"returnCode":"SUC0000","errorMsg":null,"data":{...},"sessionId":null,"type":"DONE"}
```

- `returnCode`：`SUC0000` 成功；`ERR4010` 认证失败；`ERR9999` 系统异常。行内完整码表未在文档中给出，本地补充码见第 12 节。
- `type:"DATA"`：流式数据帧。Prompt/流式 API 输出的内容增量经此帧下发（本地约定增量放 `data.output`）。
- `type:"DONE"`：尾帧，`data` 为结束节点声明的最终输出对象。
- `sessionId`：会话标识，行内示例值为 null；本地以 runId 填充以贯穿一次运行。
- 流式生效条件（行内约束）：结束节点或中间信息输出节点开启流式输出开关，且前置为 Prompt/流式 API/流式子编排/Agent 等可流式节点；仅 1 个 API 节点直连结束节点时输出为多个 data 帧，否则输出参数以字符串形式放入对应字段。

本地帧 type 全集（扩展 type 行内不存在，见第 12 节）：

| type | 性质 | data 内容 |
| --- | --- | --- |
| DATA | 行内标准 | Prompt 文本增量 `{"output": "<delta>"}` |
| DONE | 行内标准 | 结束节点输出包（resultPackage/narrative/view/degradeFlags/regenerated/durationMs） |
| START | 本地扩展 | `{"runId","mode","version","dataDate"}` |
| STAGE | 本地扩展 | `{"node","label","nodeType","payload"}`（节点过程事件） |
| ERROR | 本地扩展 | `{"errorCode","retryable","message"}`，帧级 returnCode=ERR9999 |
| HEARTBEAT | 本地扩展 | null（15 秒无事件心跳；行内是否有心跳机制待确认） |

## 4. 开始节点入参契约

- 入参类型：String（字符串）、Number（数值，含整数与浮点）、Integer（整数）、Boolean、Object（无序键值对）、File（txt/md/docx/doc/xls/xlsx/pdf/csv/wav/mp3/jpg/jpeg/png/bmp/svg）、文本。
- 约束：Object 最多 3 层嵌套；最外层变量行数最大 40 行。
- 入参即业务编排对外 API 的接口入参，以 JSON 或 FormData（文件流）传递。
- 本地对应：开始节点入参声明写在 `AI编排/metrics/<metric>/blueprint.spec.json` 的 `start` 节点；`aiworkflow.params.validate_inputs` 按声明校验，违反返回 HTTP 400（returnCode=ERR1001）。

## 5. Prompt 节点契约

- 输出格式三选：文本（默认，输出类型 string）、Markdown（string）、JSON（Object，可添加多个输出参数并设置类型）。
- JSON 输出硬约束：输出参数变量名必须英文（中文或非法字符无法转换成 JSON）；输出变量的参数必须配置，否则无法正常转换。
- 输出示例与输出结构的关系：提示词内定义了输出示例而未配置输出结构时，以 rawOutput 填充（不因结构不一致导致输出为空）；配置了输出结构则以结构为主。
- 异常忽略开关：关闭时异常中断整个编排；开启时跳过该节点继续下游，并使用默认输出替代原有输出。
- 模型高级参数（节点级）：temperature（回答多样性）、topP（采样范围）、frequencyPenalty（词汇重复惩罚）、presencePenalty（主题重复控制）、maxToken（输出 token 上限）、seed（随机种子）。
- 生成效果四档：自定义 / 创意 / 平衡 / 精确（平台预设参数组合）。
- 深度思考拆分：开启后将"思考过程"与"最终结果"拆分为 reasoningContent 与 messageContent 两个输出（String）。
- 多模态：图片入参需开始节点声明 File/Image 类型入参，选用带【图像识别】标签的模型，Prompt 内以 `${img}` 声明。
- 本地对应：`aiworkflow.graph_kit.make_prompt_node`（output_format / output_params / on_error / llm_params），LLM 参数经 `aiworkflow.llm.LLMParams` 节点级透传。

## 6. API / AI 能力 / MCP 节点契约

- API 节点：从注册列表选择（swagger 导入或新建），动态展示该接口所需输入配置项 query、body、header（及 path）；输出变量名为节点唯一标识，输出参数在 API 注册时配置。
- 复杂入参限制：API 与 AI 能力节点入参不支持复杂对象（部分版本支持 Object 展开），复杂 JSON 应由前置脚本节点构建后引用。
- AI 能力节点：插件形态与 API 一致，入参配置项同样为 query/body/header；输出如 msg/code/data。
- MCP 节点：选择已订阅/创建的 MCP Server 与其下工具，body(json) 入参，输出为 Object。
- 异常忽略开关语义与 Prompt 节点一致。
- 流式输出条件见第 3 节。
- 本地对应：`aiworkflow.tools.get_with_retry`（2xx + returnCode 双校验 + 重试）与 `aiworkflow.nodes.make_api_node`（ApiSpec 声明 + on_error + transform）。

## 7. 脚本节点契约

- 语言：python、Node.js；沙箱实现，仅沙箱白名单库可用（引用其他库需运营人员开通）。
- 为保证沙箱稳定，不支持 IO 操作（文件读写、HTTP 调用等）。
- 节点前置点超时时间 3 秒。
- 入参：输入定义的参数作为 `params` 对象属性传入，代码经 `params.get("name")` 获取。
- 返回：方法处理结果不可以修改结构、须在一个方法里处理；即使仅一个输出值也必须以对象（dict）形式返回。
- 输出：输出变量类型为 Object 时可配置输出参数 key（变量名 + 变量类型，可从 JSON 导入），后置节点单独引用。
- 异常忽略开关语义同上。
- 本地对应：`aiworkflow.nodes.make_script_node`（handler(params) 纯同步函数、返回必须为 dict、超时默认取 `SCRIPT_NODE_TIMEOUT_SECONDS`=3.0、on_error/default_output）。

## 8. 条件选择器契约

- 分支：IF / ELSEIF（可多个）/ ELSE；执行到满足条件的分支时走对应后继节点。
- 条件三元组：引用变量（或自定义内容）、操作符、比较值。
- 分支内多条件逻辑 AND/OR 可切换：AND 全部满足走 IF；OR 任一满足走 IF。
- 本地对应：`aiworkflow.nodes` 的条件操作符集（eq/ne/gt/ge/lt/le/contains/startswith/endswith/is_empty/not_empty）与 `route_when` 路由构造。

## 9. 循环组件 / 业务编排 / Agent / RAG / 中间信息输出 / 结束

- 循环组件：遍历数组对象，循环次数由引用数组长度决定；多轮严格串行、不支持并发；不支持嵌套循环；中间变量跨轮共享（可重置）；输出固定为数组（Array<Object>）。
- 业务编排节点：引用已有编排作为子流程；嵌套不能超过 2 层；不能引用自身或父级编排（平台做循环校验）；输入数据类型须与子编排入参一致。
- Agent 节点：模型自主规划工具调用；工具可挂 API/AI 能力/业务编排/MCP/多模态模型；工具调用失败支持重试一次；支持 Function call 与 ReAct 两种模式；输出固定 Object（steps 执行步骤数组 + output 最终结果等）；工具入参可配置"对 Agent 不可见"并给默认值。
- RAG 节点：知识库检索策略（混合检索=ES+向量化并行、关键字检索=仅 ES、语义检索=仅向量化）、最大召回段落数、总召回片段阈值、是否返回知识来源；输出为数组（元素含 content 等）；多知识库可配，支持目录/文件 ids 过滤（`["id1","id2"]` 或 `"id1,id2,id3"` 两种形态）。
- 中间信息输出节点：向用户输出中间消息；输出类型 String 或 Object；可视化/自定义两种配置；串在流程中使用；流式输出要求前置节点可流式（Prompt/流式 API/流式子编排/Agent）。
- 结束节点：从流程取参数组合成 JSON 作为最终输出；可视化（参数名+引用）或自定义（JSON 模板 + `${}` 插值）；流式输出开关见第 3 节；支持自定义历史上下文（会话上下文保留轮数 0–100、有效期天数）。

## 10. 函数表达式清单

变量值可切换为表达式来源，由操作数与运算符组成。已确认的函数族（按行内文档）：

- 计算：SUM、SUBTRACT、MULTIPLY、DIVIDE、AVERAGE、MAX、MIN、ABS、RAND、MOD、INT、ROUND、TFIXED（小数超出 9 位截断；数值不超过 2^53-1）。可直接用运算符连接（如 `1+2+3+4`、`9-8-2`、`10/3`）。
- 日期：NOW、DATE、TIMESTAMP、YEAR、MONTH、DAY、HOUR、MINUTE、SECOND、TODAY、DATEFORMAT、DATEMODIFY。
- 文本：LEN、ISEMPTY、CONCATENATE、LOWER、UPPER、TRIM、STARTSWITH、ENDSWITH。
- 数组：JOIN、SPLIT、LEN、CONTAINS。
- 对象：PICK、OMIT。
- 逻辑：AND、OR、NOT、IF、GE、LE、GT、LT、XOR（可用运算符 `&&`、`||`、`!`）。
- 加密：BASE64ENCODE、BASE64DECODE。
- 类型转换：TOBOOLEAN、TOJSONSTRING、TOOBJECT。
- 脱敏：DESENSITIZE（规则码含 NAME、ID_CARD、BANK_CARD、MOBILE_PHONE、FIXED_PHONE、EMAIL、ADDRESS、COMPANY_NAME、EXPIRATION_TIME、PASSPORT_NO 等）。

## 11. 平台约束清单（迁移校验 checklist）

本地设计与验收应逐条对照；其中回边、循环嵌套、子编排深度、入参声明、Prompt 输出命名与脚本返回形态已由 `aiworkflow.workflow_check` 与节点构件在装配期/运行期强制（见第 1 节末尾说明）：

1. 画布为 DAG，无回边（循环组件的子流程除外）；"校验失败回到生成节点"这类重生成环在行内无法直接表达，须线性展开或放弃。
2. 循环组件不支持嵌套，多轮严格串行。
3. 业务编排节点嵌套不超过 2 层，禁止自引用与父级引用。
4. 开始节点入参 Object 最多 3 层嵌套，最外层变量最多 40 行。
5. Prompt 节点 JSON 输出参数变量名必须英文、必须配置。
6. 脚本节点无 IO、超时 3 秒、仅白名单库、必须返回对象。
7. API/AI 能力节点入参避免复杂对象；复杂 JSON 由前置脚本节点组装。
8. 引用只沿连线可达方向；并行分支互不引用。
9. 流式输出须满足第 3 节的拓扑条件。

## 12. 本地扩展与行内差异（迁移时必须显式处理）

本地为调试与过程可见性增设的约定，行内平台不存在，迁移时逐项处理：

1. 扩展帧 type（START/STAGE/ERROR/HEARTBEAT）：迁移后过程可见性由中间信息输出节点承担，STAGE 信息不再下发或改为行内等价机制。
2. `data.output` 作为文本增量载体：行内 Prompt 流式的确切增量字段以实际网关为准，接入时校正。
3. 错误码 ERR1001（参数非法）为本地补充；行内完整码表待确认后对齐。
4. heartbeat：行内文档未提及，是否有等价机制待确认。
5. 受控门禁（schema + 数值回填校验 + 重生成 ≤1 次）：行内落点为脚本节点 + 条件选择器的线性组合；因画布无回边，重生成环节迁移时展开为"生成、校验、条件分支、失败降级（或固定的修正副本）"，或放弃重生成直接降级。
6. degradeFlags：行内无一等概念，由各节点异常忽略开关 + 默认输出 + 后续条件分支组合实现同义行为。
7. 请求体外壳 `{"inputs":{...},"user":...}` 与触发端点路径为本地约定；行内触发 API 的确切请求体形态待确认后对齐。
8. `sessionId` 本地取 runId；行内为会话标识（配合历史上下文管理），接入时与会话体系对齐。
