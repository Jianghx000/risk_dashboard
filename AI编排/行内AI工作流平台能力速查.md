# 行内 AI 工作流平台能力速查

> 来源：同目录 `行内AI工作流平台.docx`，2026-09-23 整理。该 DOCX 包含 17 个嵌入的网页内容片段；本文件按实际设计问题重新索引，不替代平台实测或最新平台公告。文末的 `afchunk` 编号可用于回查原文。文档中的示例模型、域名、参数及界面状态可能随平台版本变化。

## 先看结论

| 设计问题 | 平台已有能力 | 必须放在平台之外或待实测的部分 |
| --- | --- | --- |
| 首次解读与后续追问 | 开始节点、条件选择器、Prompt、API、脚本、结束节点；可用 `sessionId` 保留多轮上下文 | 前端须传清楚页面筛选条件、入口、分析当期；不要仅靠聊天记忆保持精确业务口径 |
| 按用户问题选择数据 | 条件选择器、脚本、Prompt JSON 输出、API 节点 | 平台文档没有证明其可直接智能查询数据仓库；应由 IT 提供受控的分析 API |
| 改币种或比较基期后重新归因 | 每轮重新解析并校验参数，API 节点带参数调用 | 正式指标计算、Owen 归因、权限与数据勾稽在后端完成，不放在模型或脚本节点 |
| 逐级展开指标计算树 | API 可按 `nodeCode` 请求，条件节点可分支 | 树结构及数值由后端服务维护；只返回当前层所需节点 |
| 大量逐笔明细 | API 可接收复杂对象和数组参数，脚本可裁剪响应 | 分页、授权、汇总和筛选由后端完成；不要把明细全量塞入 Prompt 或循环节点 |
| 长回答流式输出 | Prompt、Agent、流式 API、子编排可在满足拓扑条件时流式输出 | 首帧需早于 90 秒网关限制；JSON Prompt 和部分节点链不支持真正逐 token 流式 |

这里的“支持”只表示文档列有节点和配置能力。API 可达性、用户身份透传、多轮状态、模型质量和运行时延仍需在行内试运行验证。

## 编排骨架与输入输出

- 业务编排由固定且唯一的开始、结束节点和中间节点组成。一个应用可有多个独立业务编排。可调试节点输入、输出、耗时和 token；可复制编排、查看历史版本并对比版本。编排保存后可作为应用 OpenAPI 中的 workflow 服务调用。
- 开始节点 JSON 入参支持 `String`、`Number`、`Integer`、`Boolean`、`Object`；含文件时可选 FormData 的 `File`、`Text`。原文注明开始节点 `Object` 最多三层嵌套，最外层变量最多 40 行。前端最好传扁平、明确的机构、币种、频率、日期、口径和入口编码。
- 节点入参可引用上游输出、系统/环境变量，或使用静态值、函数表达式。引用必须存在可追溯的上下游连线；并行分支的输出不能天然互相引用。对象输出需配置正确的英文属性名及类型。
- 结束节点可输出自定义 JSON、上游结果或异常结果；也可配合中间信息输出节点分段返回。若保留会话上下文而主要用中间节点输出，原文要求在结束节点自定义历史输入和输出。
- 文件上传/下载并非本项目常规指标分析的首选路径。原文给出的编排文件上限为 5 MB，下载文件保存一天；不要以文件上传取代受控数据 API。

## 节点能力与硬限制

| 节点 | 适合承担 | 原文明确的限制或注意事项 |
| --- | --- | --- |
| Prompt | 问题分类、抽取币种/基期、基于小数据包生成解释 | 支持文本、Markdown、JSON 输出。JSON 输出须配英文变量和字段结构，且不支持流式。选择模型和高级参数由平台配置决定。 |
| 条件选择器 | 首次/追问分流、是否支持归因、数据异常分流 | 支持等于、不等于、大小、包含、空值及 AND/OR；原文称最多嵌套 5 层。复杂路由宜先在脚本节点归一化。 |
| API | 调用已注册的 ALM 指标、归因、分布或明细服务 | 通过 API 注册配置 query/body/header/path。API 节点说明称支持复杂 `Object` 入参及 `Array` 根引用；接口可达性、鉴权、超时和输出结构必须实测。 |
| 脚本 | 参数校验、日期归一化、结果裁剪、数值勾稽、构造 API 请求 | Python 3.9、Node.js 14；仅沙盒内库可用；不支持文件读写、HTTP 等长 IO；超时 5 秒；`handler(params)` 必须返回对象。**不能承担正式复杂归因计算。** |
| 业务编排 | 复用已有子流程 | 最多嵌套两层，子编排中不能再嵌套子编排；不能引用自身或父编排。输入类型要与子编排声明一致。 |
| RAG | 查找管理办法、指标口径等非结构化文档 | 需配置并订阅知识库；检索返回片段，不是智能查询数据仓库的替代品。可返回来源。 |
| AI 能力 / MCP | 使用已订阅的公共能力或工具 | 具体能力取决于订阅与注册。文档对复杂参数的描述不一致，见“需实测”。 |
| Agent | 模型自主选择工具的开放式任务 | 原文明确工具选择和执行轮数不能达到 100% 准确；银行指标取数、归因主链不应依赖 Agent 自主规划。 |
| 循环组件 | 对少量已知数组逐项处理 | 严格串行；不支持嵌套循环；原文明确不适合大规模批处理。 |
| 中间信息输出 | 返回等待提示、阶段性结果或分支信息 | 可输出 `Object` 或 `String`；流式仍受上游节点与结束节点配置限制。 |
| 结束 | 汇总最终结果、定义异常或流式输出 | 可视化/自定义输出；与历史上下文和中间输出联用时注意存储配置。 |

## 多轮会话与精确状态

**2026-10-08 用户行内实测补充（优先于下文文档推断）：** 开始节点整体对象可直接引用。系统 `chatHistory` 可独立绑定到脚本，值为数组；每项 inputMessage/outputMessage 均为 JSON 字符串。第二轮历史含第一轮输入和结束输出，不含当前问题，也未自动包含脚本中间标记。结束输出中的结构化状态可通过此渠道恢复，不要求页面额外逐项回传。正式 OpenAPI 的 sessionId 衔接仍需联调。结束输出不要再次包含完整历史，以免递归嵌套。脚本沙盒实测禁止 `__name__` 属性访问。

1. 编排可开启历史上下文，系统变量 `chatHistory` 可被后续节点引用；Prompt 节点也可按 `sessionId` 参考上下文。平台默认保存单轮输入与输出，可在结束节点自定义。会话最长保留 168 小时（7 天），实际轮数可配置。
2. OpenAPI 调用时传平台生成的 `sessionId`：空值会生成新会话，复用原值才可读取同一会话历史。开启会话后，开始节点有 `question` 和 `chatHistory`；首次解读可用空问题配合明确的 `entryMode=initial` 分流，具体入参在试运行中验证。
3. 对 ALM 不应只让模型从 `chatHistory` 猜“它”“上期”指什么。页面范围每轮明确传入；关注币种、业务类别和基期从最新 outputMessage 的 conversationState 解析并校验。用户从人民币追问美元，再问“它为什么变化”时，对话关注币种是美元，但页面筛选币种不变。
4. 用户指代不清或指定日期不存在时，返回澄清或明确不可用状态；不能静默替换成另一币种或最近日期。模型可提取意图，脚本和后端必须验证实体与权限。

## API 与数据包设计

- 数据仓库是底层来源，不把整仓数据、全部时点或全量逐笔明细送进 Prompt。后端分析 API 根据已授权的机构、币种、日期、口径返回本轮小数据包。
- API 节点调用事先注册的接口。业务上可分“指标概览”“正式归因”“计算节点”“业务期限分布”“分页逐笔明细”等能力，但**逻辑能力数不等于工作流节点数，也不必等于物理 API 数**。
- 后端负责指标、限额适用、正式归因、币种折算、分页及勾稽；脚本只负责轻量校验、字段筛选和状态规范化；Prompt 只基于已验证结果做解释。
- 建议每份结果都返回 `status`、实际数据日期、机构/币种/口径、计算版本、数值单位、权限或不可用原因。任意两期归因请求显式携带 `currentDate` 和 `baseDate`，结果带贡献合计校验。逐级展开可携带 `nodeCode`。
- 不建议在工作流中为每个币种循环调 API。让后端一次返回有界的币种摘要，或按用户追问只取目标币种。循环节点串行且不适合大批量处理。
- API 节点支持复杂入参的说明与 AI 能力节点页面中“API 和 AI 能力节点不支持复杂入参”的说法冲突。设计时优先采用扁平参数或在脚本中构造 JSON，并以行内实际 API 节点版本验证。

## 流式输出与性能

- 文档称 OpenAPI 存在约 90 秒的 504 网关限制，且**流式首帧也必须在 90 秒内出现**。流式不能弥补前置数据接口或归因计算耗时过长。
- 可流式的上游节点包括 Prompt、Agent、已配置流式的 API、满足条件的子编排。上游流式节点到结束或中间信息输出节点须符合“一对一输出”拓扑；多个流式上游汇到一个输出节点会等齐后一次返回。
- Prompt 流式输出须使用**文本格式**；Markdown/JSON Prompt 输出不支持逐 token 流式。经过脚本节点等需要完整上游结果的节点时，后续输出可能变为非流式。
- 如果需要结构化校验与稳定数值引用，优先采用 JSON/非流式；若要改善等待体验，可用中间信息输出提示进度，但不可把进度提示当成归因已完成。
- 正式归因服务应评估耗时、并发和缓存。平台脚本 5 秒超时不承担计算；需在行内测试端到端时延。

## 函数表达式速查

函数表达式适合节点入参中的简单变换，不适合银行指标正式计算。常见函数：

| 用途 | 原文列出的函数 |
| --- | --- |
| 数值 | `SUM`、`SUBTRACT`、`MULTIPLY`、`DIVIDE`、`AVERAGE`、`MAX`、`MIN`、`ABS`、`ROUND`、`TOFIXED`、`INT` |
| 日期 | `NOW`、`TODAY`、`DATE`、`TIMESTAMP`、`YEAR`、`MONTH`、`DAY`、`DATEFORMAT`、`DATEMODIFY` |
| 文本/数组 | `LEN`、`ISEMPTY`、`CONCATENATE`、`TRIM`、`LOWER`、`UPPER`、`JOIN`、`SPLIT`、`CONTAINS` |
| 对象/类型 | `PICK`、`OMIT`、`TOBOOLEAN`、`TOJSONSTRING`、`TOOBJECT` |
| 逻辑 | `AND`、`OR`、`NOT`、`IF`、`GE`、`LE`、`GT`、`LT`、`XOR` |
| 脱敏 | `DESENSITIZE`，原文列有姓名、证件、银行卡、电话、邮箱等规则 |

原文指出数值运算结果最多保留小数点后 9 位，数值不应超过 JavaScript 安全整数 `2^53-1`。因此金额、比率和归因贡献不要靠平台表达式做最终权威计算。表达式章节里有个别示例与函数名对调或疑似笔误，具体语法应在表达式调试区验证。

## 本项目的默认设计约束

1. 首次解读和用户追问都在工作流中，但首次不依赖用户提问；每次仅传当前场景所需的小数据包。
2. 页面上下文与对话关注对象分开保存。机构、币种、当期、基期和口径由前端显式传入或由受控状态恢复，不能只靠自然语言记忆。
3. 重定价缺口率默认以前一可比期做首次归因；用户改基期后，重新调用正式归因服务。只有正式支持的口径可给出归因，非默认口径不得套用默认结果。
4. “分业务重定价期限分布”与“逐笔重定价明细”是汇总与联动穿透关系；明细不能替代正式指标归因。
5. 资产负债重定价久期缺口目前只有指标值及资产/负债久期展示，不具有正式计算过程或因素归因；不要与重定价缺口率混为一条归因分支。
